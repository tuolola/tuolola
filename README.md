## 关于我

我正在围绕 **AI 辅助软件工程与 AI 编程工具** 做产品实践：把需求分析、UML 建模、测试设计和文档编写串起来，也让 AI 编程会话能从电脑延续到手机。

比起一次生成很多内容，我更关心：**设计从哪里来、需求变化后要改哪里、产物能不能继续编辑和验证。**

- 🧩 **AI × 软件工程**：用模型辅助分析与设计，保留需求、模型和测试之间的来源关系。
- 💻 **跨端 AI 工具**：通过 Web、Windows 桌面和 Android 原生应用，把建模与编程工作流带到不同设备。
- 🛠️ **从原型到工具**：持续打磨交互、失败重试、历史记录与文档导出，让功能融入完整的使用流程。

## 主要项目

围绕 AI 辅助建模与 AI 编程，持续维护以下开源项目：

| 项目 | AI 应用方向 | 主要技术 |
| :--- | :--- | :--- |
| **[SoftJL Community](https://github.com/tuolola/SoftJL)** | 自托管 AI 软件工程工作台，关联需求、UML、设计、测试与工程说明书，支持自带 OpenAI 兼容模型服务。 | TypeScript · React · Next.js · Fastify · PlantUML |
| **[SoftJL Desktop](https://github.com/tuolola/softJL-desktop)** | Windows 本地 AI 建模工作台，支持对话建模、分阶段工程建模与 Word 文档导出；项目和历史保存在本机，使用自带模型服务。 | TypeScript · Electron · React · Fastify · Zod |
| **[CC Android Tunnel](https://github.com/tuolola/cc-android-tunnel)** | 用 Android 原生客户端连接自己的 CC Desk Tunnel 工作台，在手机上延续 Claude Code 会话，查看流式回复与工具执行，管理会话和模型设置。 | Kotlin · Jetpack Compose · WSS |

SoftJL 提供 Web 自托管与 Windows 本地两种使用方式；CC Android Tunnel 提供 AI 编程工作台的手机入口。

> CC Android Tunnel 基于 [sun168567/cc-desk-tunnel](https://github.com/sun168567/cc-desk-tunnel) 独立维护，是非官方 Android 原生移植，需配合上游服务端使用。

## 正在关注

- **需求追溯与变更影响**：从一条需求找到关联模型、测试和待复核的材料。
- **可检查的 AI 工作流**：提供过程状态、来源信息和重试入口，让生成结果便于检查与修正。
- **模型服务接入**：支持自带 OpenAI 兼容模型服务，关注调用过程与实际用量。
- **工程产物交付**：让图表、测试用例与可编辑文档衔接起来，方便后续修改和说明。
- **移动端 AI 编程体验**：关注长会话阅读、流式输出、工具结果展示与断线后的会话恢复。
