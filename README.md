## 关于我

我正在围绕 **AI 辅助软件工程** 做产品实践，希望让需求分析、UML 建模、测试设计和文档编写能在同一套工作流里衔接起来。

比起一次生成很多内容，我更关心：**设计从哪里来、需求变化后要改哪里、产物能不能继续编辑和验证。**

- 🧩 **AI × 软件工程**：用模型辅助分析与设计，保留需求、模型和测试之间的来源关系。
- 🖥️ **Web × Desktop**：通过 Web 应用和 Windows 桌面应用提供不同的使用方式。
- 🛠️ **从原型到工具**：持续打磨交互、失败重试、历史记录与文档导出，让功能融入完整的使用流程。

## 主要项目

| 项目 | 在做什么 | 主要技术 |
| :--- | :--- | :--- |
| **SoftJL Community** | 面向软件类毕设与课程设计的自托管工作台，关联需求、UML、测试和工程说明书，支持自带模型服务。 | TypeScript · React · Next.js · Fastify · PlantUML |
| **SoftJL Desktop** | Windows 本地建模工作台，项目与历史保存在自己的电脑里，支持对话建模、分阶段工程建模和 Word 文档导出。 | TypeScript · Electron · React · Fastify · Zod |

两种工作流，一个目标：**需求改得动，设计查得到，成果讲得清。**

## 正在关注

- **需求追溯与变更影响**：从一条需求找到关联模型、测试和待复核的材料。
- **可检查的 AI 工作流**：提供过程状态、来源信息和重试入口，让生成结果便于检查与修正。
- **模型服务接入**：支持自带 OpenAI 兼容模型服务，关注调用过程与实际用量。
- **工程产物交付**：让图表、测试用例与可编辑文档衔接起来，方便后续修改和说明。
